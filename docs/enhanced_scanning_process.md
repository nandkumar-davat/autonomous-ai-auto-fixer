# Enhanced Scanning Process with Scanner-Specific Fix Methodologies\n\n## Overview\n\nThe autonomous AI auto-fixer now uses specialized, systematic fix methodologies for each scanner type. These methodologies follow structured 5-step processes designed to ensure comprehensive and reliable vulnerability remediation.\n\n## Updated Scanning Architecture\n\n### 1. Scanner-Specific Processing\n\nEach scanner type now has dedicated fix processing:\n\n- **Mend Security Scanner**: Uses `mend_security_fixer.md` prompt\n- **Trivy Security Scanner**: Uses `trivy_security_fixer.md` prompt  \n- **SonarQube Quality Scanner**: Uses `sonarqube_issue_fixer.md` prompt\n\n### 2. Systematic Fix Methodology\n\nAll scanner-specific prompts follow a standardized 5-step approach:\n\n1. **Parse Scan Results** - Understand report structure and extract findings\n2. **Categorize by Priority** - Process vulnerabilities by severity (CRITICAL → HIGH → MEDIUM → LOW)\n3. **Apply Fixes Systematically** - Use scanner-specific fix strategies\n4. **Generate Fix Summary** - Provide structured documentation of changes\n5. **Create Structured Commits** - Follow conventional commit format\n\n### 3. Enhanced Fixer Agent\n\nThe `FixerAgent` has been enhanced with:\n\n- **Scanner-aware prompting**: Automatically selects the appropriate methodology based on finding source\n- **Contextual fix generation**: Includes scanner-specific metadata (CVE IDs, rule IDs, recommended fixes)\n- **Fallback handling**: Uses default fixer behavior for unknown scanner types\n\n## Implementation Details\n\n### Prompt Files Structure\n\n```\nsrc/autofixer/agents/prompts/\n├── mend_security_fixer.md       # Mend vulnerability fix methodology\n├── trivy_security_fixer.md      # Trivy vulnerability fix methodology \n├── sonarqube_issue_fixer.md     # SonarQube code quality fix methodology\n├── fixer.md                     # Default fixer prompt (fallback)\n└── loader.py                    # Enhanced prompt loader\n```\n\n### Key Enhancements\n\n#### 1. Priority-Based Processing\n- **Critical/Blocker**: Immediate processing\n- **High**: High priority after critical\n- **Medium/Major**: Medium priority\n- **Low/Minor**: Lowest priority\n\n#### 2. Scanner-Specific Intelligence\n\n**Mend Scanner:**\n- Processes `topFix.fixResolution` recommendations\n- Handles library version upgrades\n- Manages transitive dependency updates\n- Prioritizes exploitable vulnerabilities\n\n**Trivy Scanner:**\n- Handles both container and application vulnerabilities\n- Manages zero-day vulnerabilities (no fixed version available)\n- Updates Dockerfiles and dependency files\n- Implements mitigation strategies when fixes unavailable\n\n**SonarQube Scanner:**\n- Focuses on BUG and VULNERABILITY types only\n- Filters by BLOCKER/CRITICAL severity\n- Applies rule-specific fixes (SQL injection prevention, security headers, etc.)\n- Maintains code quality standards\n\n#### 3. Enhanced Context Passing\n\nThe fixer now passes rich context to the LLM:\n- Scanner type and source tool\n- CVE/vulnerability IDs\n- SonarQube rule IDs\n- Recommended fix versions\n- Exploit availability status\n\n## Usage Examples\n\n### Mend Vulnerability Fix\n```\nfix(security): resolve Mend vulnerabilities in ProjectName\n\n- CVE-2023-1234: Update jackson-databind to v2.15.2 (CRITICAL)\n- CVE-2023-5678: Update spring-security to v5.8.4 (HIGH)\n\nLibrary updates:\n- jackson-databind: v2.13.0 → v2.15.2\n- spring-security: v5.6.0 → v5.8.4\n\nFiles modified:\n- pom.xml\n- gradle.properties\n```\n\n### Trivy Security Fix\n```\nfix(security): resolve 2 critical and 3 high Trivy vulnerabilities\n\n- CVE-2023-9999: Update nginx to v1.24.0 (CRITICAL)\n- CVE-2023-8888: Update openssl to v3.1.1 (HIGH)\n\nAffected packages:\n- nginx: v1.20.2 → v1.24.0\n- openssl: v3.0.5 → v3.1.1\n\nFiles modified:\n- Dockerfile\n- requirements.txt\n```\n\n### SonarQube Quality Fix\n```\nfix(quality): resolve 1 blocker and 2 critical SonarQube issues\n\n- ABC123: Fix csharpsquid:S3649 in UserController.cs\n- DEF456: Address vulnerability csharpsquid:S2092 at line 45\n\nRules addressed: [S3649, S2092, S1234]\nFiles modified:\n- Controllers/UserController.cs\n- Models/AuthConfig.cs\n```\n\n## Configuration\n\nThe enhanced scanning process requires no additional configuration. The system automatically:\n1. Detects the scanner type from finding metadata\n2. Loads the appropriate scanner-specific prompt\n3. Applies the systematic fix methodology\n4. Generates structured commit messages\n\n## Benefits\n\n1. **Consistency**: Standardized approach across all scanner types\n2. **Reliability**: Systematic methodology reduces fix errors\n3. **Traceability**: Clear documentation of all changes\n4. **Prioritization**: Critical issues addressed first\n5. **Intelligence**: Scanner-specific best practices applied\n6. **Scalability**: Easy to add new scanner types\n\n## Next Steps\n\n1. **Validation**: Run end-to-end tests with sample scan results\n2. **Monitoring**: Track fix success rates by scanner type\n3. **Expansion**: Add support for additional scanners (Snyk, Checkmarx, etc.)\n4. **Optimization**: Refine prompts based on real-world performance\n5. **Integration**: Connect to CI/CD pipelines for automated fixing\n"
